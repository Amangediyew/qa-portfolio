# Шаблон баг-репорта

Копируйте шаблон в новый файл `bugs/BUG-XXX-краткое-название.md` или создавайте GitHub Issue.

```
## BUG-XXX: [Модуль] Краткое название — что не так

**Статус:** New
**Severity:** Blocker / Critical / Major / Minor / Trivial
**Priority:** High / Medium / Low
**Дата обнаружения:** ГГГГ-ММ-ДД
**Автор:** Амангельдыев Эзиз

### Окружение
- Приложение: https://www.saucedemo.com
- Браузер / версия:
- ОС:
- Пользователь:

### Предусловия
...

### Шаги воспроизведения
1.
2.
3.

### Фактический результат
...

### Ожидаемый результат
...

### Вложения
Скриншот / видео / логи консоли / HAR

### Примечания
Частота воспроизведения (например, 3 из 3), связанные тест-кейсы, возможная причина.
```

## Правила хорошего баг-репорта
1. Одно описание — один дефект.
2. Заголовок отвечает на вопрос «где и что не так».
3. Шаги короткие, нумерованные, воспроизводимые с нуля.
4. Фактический и ожидаемый результат разделены.
5. Всегда есть скриншот, а для динамики — видео.
6. Указано окружение и пользователь.
7. Баг перепроверен минимум 2 раза.

## Жизненный цикл бага
`New` → `Open` → `In Progress` → `Fixed` → `Verified` → `Closed`
(при повторении: `Reopened`; при непонимании: `Need info`; без правки: `Won't fix` / `Duplicate` / `Not a bug`)
